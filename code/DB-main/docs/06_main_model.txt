꼿꼿 AI 메인 모델 YOLO11s-pose 학습·검증과 후보 모델 평가

1. 메인 모델 개요
서비스 로봇 모듈에서 학습해서 쓰는 모델은 YOLO11s-pose 하나입니다. 이 모델을 기준으로 학습 5단계, 검증 4단계를 거칩니다.

2. 학습 1단계: 데이터 수집
로봇에 실제 모듈을 장착한 상태로 공장과 사무실에서 동의한 참여자만 촬영합니다. 연속 프레임은 거의 같은 이미지라 학습 효과 없이 라벨링 비용만 늘기 때문에, 1초에 1~2장씩 뽑아 3,000~5,000장을 모읍니다. 거리(1~2m / 2~3.5m / 3.5~5m), 시점(정면·측면·대각선), 복장(안전모·조끼·사무복), 가림 정도, 조명(주간·야간)별 장수를 표로 관리하고, 부족한 조건만 추가로 촬영합니다.

3. 학습 2단계: 라벨링
큰 모델(RTMPose-x 등)로 관절 17개를 자동으로 찍은 뒤, 사람이 CVAT에서 틀린 점만 고칩니다. 각 관절에는 "보임 / 가려짐 / 화면 밖" 표시를 함께 답니다. 가려진 관절을 억지로 찍거나 빼먹지 않도록 라벨링 가이드를 먼저 만들고, 전체의 10%는 두 명이 따로 라벨링해 일관성을 확인합니다.

4. 학습 3단계: 데이터 분할
학습 70%, 검증 15%, 테스트 15%로 나누되, 이미지 단위가 아니라 촬영 세션·사람·장소 단위로 나눕니다. 같은 사람, 같은 장면이 학습과 테스트에 함께 들어가면 성능이 부풀려지기 때문입니다. 테스트 세트에는 학습에 없는 작업 구역과 야간 영상을 일부러 넣고, 최종 평가 전까지 보지 않습니다.

5. 학습 4단계: 2단계 미세조정
COCO로 사전학습된 YOLO11s-pose의 백본 10개 층을 고정하고 30에폭 학습해, 사전학습 지식을 지키면서 출력부만 현장에 맞춥니다. 이어서 고정을 풀고 최대 150에폭 학습하며, 30에폭 동안 성능이 오르지 않으면 조기 종료합니다. 하이퍼파라미터는 imgsz 640, AdamW, lr0 0.001, 코사인 스케줄, scale 0.5, mixup 0입니다.

6. 학습 5단계: 오류 분석과 반복
검증 세트에서 틀린 이미지를 조건별로 모아 봅니다. 예를 들어 "야간 + 측면 + 4m 이상"에서 유독 틀린다면 그 조건의 데이터를 추가 수집해 다시 학습합니다. 이 반복을 2~3회 하는 것이 하이퍼파라미터 조정보다 성능 향상에 훨씬 효과적입니다.

7. 검증 1단계: 모델 정확도 (오프라인)
테스트 세트에서 OKS-AP(포즈 추정 표준 지표)를 잽니다. 평균은 좋은데 특정 조건에서 무너지는 경우를 찾기 위해 거리·시점·가림·복장·조명별로 나눠서 봅니다. 미세조정 전 COCO 모델의 점수를 같은 테스트 세트에서 재서 현장 학습 효과를 확인하고, 자세 판정에 직접 쓰이는 귀·어깨·골반·무릎의 오차는 따로 확인합니다.

8. 검증 2단계: 각도 정확도 (실측 비교)
키포인트가 정확해도 최종 각도가 틀리면 소용없습니다. 참여자가 IMU 모션캡처 슈트를 입고 여러 자세를 취하게 한 뒤, 로봇이 계산한 몸통·목 각도와 슈트가 측정한 실제 각도를 비교합니다. 목표는 평균 오차 10° 이내입니다. 이 값을 거리·시점별로 나눠 보면 로봇이 몇 m, 어느 각도에서 관찰해야 하는지 기준이 나옵니다.

9. 검증 3단계: 로봇 탑재 성능
TensorRT로 변환한 뒤 실제 엣지 보드에서 같은 테스트를 다시 돌립니다. 변환 전 대비 OKS-AP 하락이 1~2포인트 이내인지, 처리 속도가 15fps 이상인지 확인합니다. 둘 중 하나라도 못 맞추면 FP16 유지나 YOLO11n-pose로 교체를 검토합니다.

10. 검증 4단계: 현장 섀도 운영
알림을 끈 채로 2~4주간 실제 현장에서 운영하면서, 같은 기간 인간공학 전문가의 관찰 평가와 비교합니다. 기준을 통과하면 알림을 켜고 정식 운영에 들어갑니다.

11. 통과 기준
몸통·목 각도 평균 오차는 IMU 슈트 대비 10° 이내, TensorRT 변환 후 OKS-AP 하락은 1~2포인트 이내, 엣지 보드 처리 속도는 15fps 이상, 전문가 판정과의 일치도는 Cohen's kappa 0.6 이상, 근로자당 시간당 오알림은 1회 미만, UWB 오전송률은 1% 미만이어야 합니다.

12. 후보 모델 평가 요약
YOLO11s-pose 외에 후보 모델 6종을 검토했습니다. 로봇의 자세 감지는 YOLO11s-pose가 맡고, 후보 모델은 안전장비·학습 데이터 제작·B2C 버전에 쓸 수 있는지 평가했습니다. 보조 도구로 활용하는 모델은 YOLOE, SAM 3, SigLIP이고, B2C 버전에 적합한 모델은 MediaPipe이며, 사용하지 않는 모델은 DINO-X와 OCR입니다.

13. YOLOE: 안전장비 감지 단계에서 유용
"안전모", "안전 조끼"처럼 텍스트만 입력하면 따로 학습하지 않아도 해당 물체를 찾는 개방형 검출 모델입니다. YOLO 계열이라 엣지에서도 빠릅니다. 안전장비 기능 시제품을 학습 데이터 없이 바로 시연할 수 있고, 현장 이미지에 안전모 라벨을 자동으로 달아 학습 데이터 제작을 가속할 수 있습니다. 다만 관절을 뽑지 못해 자세 감지에는 쓸 수 없고, 최종 제품에서는 현장 데이터로 학습한 전용 모델이 보통 더 정확합니다.

14. SAM 3: 학습 데이터 제작용으로 유용
텍스트 개념으로 물체를 찾아 픽셀 단위로 정밀하게 분할하는 모델로, 로봇이 아닌 사내 서버에서 학습 데이터를 만들 때 씁니다. 안전모·조끼의 정밀한 영역 라벨을 빠르게 제작하고, 공장 사진에서 기계·선반·박스를 잘라 사람 이미지 위에 합성하는 가림 증강에 씁니다. 무거워서 로봇에 올릴 수 없고 관절을 뽑지 못합니다.

15. SigLIP: 데이터 관리와 안전장비 분류에 유용
이미지와 문장을 같은 공간에 놓고 비교하는 모델입니다. "어두운 공장에서 허리를 숙인 사람" 같은 문장으로 원하는 이미지를 찾고 거의 같은 이미지를 걸러내, 학습 5단계의 약한 조건 보강이 훨씬 빨라집니다. 계획했던 MobileNetV3 대신 안전장비 분류기의 기반 모델로 쓰면 적은 데이터로도 "머리 부분에 안전모가 있는가"를 잘 판정하며, 엣지 속도가 부족하면 MobileNet에 증류해 배포합니다. 검출이나 관절 추정은 못 합니다.

16. MediaPipe: 로봇에는 부적합, B2C 버전에는 최적
가볍고 무료(Apache 2.0)이며 CPU나 스마트폰에서도 돌아가는 포즈 모델로, 관절 33개와 3D 좌표까지 줍니다. 화면을 크게 채운 한 사람을 전제로 설계되어 3~5m 거리의 작은 사람에서 정확도가 떨어지고, 여러 사람과 가림에 약하며, 직접 재학습이 사실상 어려워 안전모·작업복 같은 공장 환경에 맞출 수 없어 로봇에는 부적합합니다. 반면 책상 앞 1인 사용자를 웹캠·스마트폰으로 가까이에서 보고, 별도 GPU 없이 노트북이나 휴대폰에서 동작하므로 B2C 버전에는 최적입니다.

17. DINO-X: 로봇에는 부적합
물체 검출, 분할, 사람 관절 추정까지 폭넓게 하는 대형 범용 모델로 성능은 뛰어납니다. 하지만 주로 클라우드 API로 제공되고 로봇 엣지 보드에서 실시간으로 돌리기에는 무겁습니다. 근로자 영상을 외부 서버로 보내야 해 "영상은 장치 밖으로 나가지 않는다"는 원칙과 정면으로 충돌하며, 같은 이유로 라벨링 보조로 쓰는 것도 신중해야 합니다.

18. OCR: 불필요
글자를 읽는 모델이라 자세 감지와 관련이 없습니다. 사원증·이름표를 읽는 용도는 얼굴 인식 없이 UWB로 익명 매칭한다는 설계 원칙을 스스로 깨는 일이고, 로봇 위치는 지도로 이미 알고 있어 구역 표지판을 읽을 필요도 없습니다.
